# Parity Studio (local visual editor)

Dev-only side-by-side tool for recreating **golden-wings-robyn.com** against the local webcrawl. Not WordPress. Not Keystatic/Tina. Edits the existing Markdown content files Astro already uses.

## Why this instead of Keystatic / Tina

- The crawl parity problem is visual: left = scraped HTML, right = matching MD.
- `pages` and `blog` under `src/content/` are **regenerated by ingest** on every `npm run build`, so a Git CMS pointed at those folders alone would fight the pipeline.
- Parity Studio stays out of `dist` (Vite middleware + `PARITY_STUDIO=1` only) and the Worker returns 404 for `/__parity`.

## Crawl folder (not in git)

On Caleb's machine the crawl lives at:

```text
C:\RUNB2\crawls\collections\golden-wings-full
```

Do **not** commit that tree. Point the studio at it with `CRAWL_ROOT`.

| Shell | Command |
| --- | --- |
| PowerShell | `$env:CRAWL_ROOT="C:\RUNB2\crawls\collections\golden-wings-full"; npm run parity` |
| cmd | `set CRAWL_ROOT=C:\RUNB2\crawls\collections\golden-wings-full && npm run parity` |
| WSL | `CRAWL_ROOT=/mnt/c/RUNB2/crawls/collections/golden-wings-full npm run parity` |

`npm run parity` defaults `CRAWL_ROOT` to the Windows path above (or the WSL `/mnt/c/...` equivalent) when unset.

## Run it

```bash
npm install
npm run parity
```

Open **http://127.0.0.1:4321/__parity**

Plain `npm run dev` does **not** enable the editor (no `PARITY_STUDIO=1`).

## Side-by-side workflow

1. Pick a **collection** (`pages`, `blog`, or `people`) and an **entry**.
2. Left pane loads the best-matching HTML file from `CRAWL_ROOT` (auto-scored by `path` / `sourceUrl` / slug). Override with the crawl dropdown if the guess is wrong.
3. Right pane edits frontmatter fields + markdown body for the matching file under `src/content/{collection}/`.
4. **Save markdown** writes that file. Use **Open Astro route** to preview the live page in another tab.
5. For lasting `pages` / `blog` changes, also update `../migration/content/...` (or re-copy your parity edits there). Ingest overwrites `src/content/pages` and `src/content/blog` on build. `people` is hand-written and safe.

## Production lock

| Layer | Behavior |
| --- | --- |
| `npm run parity` | Sets `PARITY_STUDIO=1` and starts `astro dev` |
| Vite plugin | Middleware registers only when `PARITY_STUDIO=1`; build never loads it |
| Worker | `frontend-worker.js` returns 404 for `/__parity` and `/parity-studio` |
| Sitemap | Filters out parity paths |

`npm run build` / `npm run deploy:staging` do not publish an open admin.

## Files

- `scripts/run-parity-studio.mjs` — launcher
- `scripts/parity-studio-plugin.mjs` — Vite middleware + APIs
- `scripts/parity-studio-ui.html` — two-pane UI
